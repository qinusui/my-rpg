# 云室 — 世界专属规则

> DM 每局开始前必须通读此文件。这些规则只在活跃世界观为 `cloud_chamber` 时生效。

## 加载顺序与边界（Core + Overlay）

1. 先读 `docs/core/rules_index.md` 与其指向的核心规则文档
2. 再读本文件的世界覆写内容
3. 若本文件与核心规则冲突：以本文件为准

本文件聚焦四类内容：
- 云室属性映射与阈值标志
- 云室专属机制（白息、枯萎症、圣水、誓言节奏等）
- 云室叙事约束与开场模板
- 对核心规则的必要覆写

## 一、属性与轨道

云室使用**四属性 + 三轨道**双轨系统。

### 属性（用于 D20 检定）

四项属性代表角色的适应性成长，范围 1-4，方向 `up`。修正值直接使用 filled 值（非中点偏移）。

| 属性 | key | 满格 | 含义 | 适用检定类型 |
|------|-----|------|------|-------------|
| 躯壳 | `躯壳` | 4 | 物理承载力、耐力、抵抗伤害 | 承受伤害、持久行动、抵抗毒素 |
| 清明 | `清明` | 4 | 精神锐度、感知力、意志力 | 察觉谎言、抵抗白息、保持专注 |
| 根系 | `根系` | 4 | 与世界/旧物的连接、知识积累 | 解读旧世界文字、操作设备、感知地脉 |
| 胆识 | `胆识` | 4 | 行动勇气、社交魄力、决断力 | 威吓、交涉、危险环境中的果断行动 |

属性靠特定经历提升（`--update 躯壳 +1`），上限 4。

### 轨道（损伤/消耗计量）

三条轨道方向为 `down`——填满意味着耗尽/崩溃。

| 轨道 | key | 满格 | 初始 | 含义 |
|------|-----|------|------|------|
| 身体 | `health` | 5 | 0 | 物理损伤——被攻击、坠落、中毒推进此轨道 |
| 清醒 | `spirit` | 5 | 0 | 精神完整度——白息侵蚀、枯萎症推进此轨道 |
| 补给 | `supply` | 5 | 2 | 圣水、食物、水——消耗时推进此轨道 |

任一轨道满格触发对应危机判定。`health`≥5 触发濒死，`spirit`≥5 触发 Face Desolation，`supply`≥5 触发断供（health 和 spirit 同时承压）。

### 阈值标志（`--view` 自动显示）

| 标志 | 触发条件 | DM 行为 |
|------|---------|--------|
| `wounded` | health ≥ 2 | 某些体力判定需额外说明 |
| `near_death` | health ≥ 4 | 触发【濒死】标签，每轮需判定维持 |
| `wither_early` | spirit ≥ 2 | DM 描述早期幻觉症状 |
| `face_desolation` | spirit ≥ 4 | DM 准备触发 Face Desolation 判定 |
| `supply_low` | supply ≥ 3 | 补给告急，每次消耗需判定是否真有效 |
| `supply_exhausted` | supply ≥ 5 | 断供，health 和 spirit 同时承压 |

### 印记系统

印记是经历留下的痕迹，提供**情境限定**的 D20 加值。不是全局 buff——只在相关场景下生效。

| 印记示例 | 加值 | 适用场景 |
|---------|------|---------|
| 见过灰质者 | +1 | 与低地生物交流判定 |
| 拆开过旧世界机器 | +1 | 面对基座设备判定 |
| 在嗜醇林存活过 | +1 | 极端环境生存判定 |
| 读懂过旧世界文字 | +2 | 旧世界文献解读（普通难度直接免除） |

```
python .claude/skills/rpg-dm/scripts/tools/state_mgr.py --add_mark "名称" --mark_bonus +1 --mark_context "适用场景"
```

### 完整判定公式

```
D20 + 属性值 + 印记加值 + 局势修正 vs DC

DC 范围: 12(简单) / 15(中等) / 18(困难) / 22(极难)
```

```
python .claude/skills/rpg-dm/scripts/tools/state_mgr.py --d20 --attr 胆识 --mark "见过灰质者" --mod ±N
```

## 二、角色创建

当 `player_name` 为 `"无名者"`（默认值）或 `scar`/`drive`/`appearance` 任一为空时触发。

角色创建共 **6 步**，严格顺序执行。每次只问一个问题（AskUserQuestion），角色创建期间不执行 `--tick`。

### 步骤判定（断点续建）

DM 先读取 state 确定当前步骤：

| 条件 | 当前步骤 |
|------|---------|
| `origin == ""` | 步骤 1（身份起点） |
| `origin != ""` 且 `scar == ""` | 步骤 2（旧伤） |
| `scar != ""` 且 `drive == ""` | 步骤 3（执念） |
| `drive != ""` 且 `appearance == ""` | 步骤 4（形貌） |
| `appearance != ""` 且属性未调整 | 步骤 5（取舍） |
| 仅 `player_name == "无名者"` | 步骤 6（命名） |

---

### 步骤 1：身份起点

DM 提供三个选项，不标明哪个来自固定池：

- 从 `origins.md` 固定池中随机抽 1 个
- DM 即兴原创 2 个（必须满足 §原创起源规范）
- 三个一起用 AskUserQuestion 呈现，label 用起源名，description 以人物处境和在乎的事物为首句

玩家选定后：`--set origin <key>`。按所选起源执行 `--set_clock`（固定起源见 origins.md，原创起源见 DM 设定的属性倾向）。`--set origin` 会自动注入起源绑定的 NPC 亲密度、初始物品和初始位置。

原创起源必须满足本文件末尾 §原创起源规范 中的全部约束。

---

### 步骤 2：旧伤 (The Scar)

DM 读取所选起源的 `scar_options`（见 `origins.md`），从中随机抽 1 个，再即兴原创 2 个。三个一起用 AskUserQuestion 呈现。

**即兴创作维度矩阵：**

| 维度 | 选项 |
|------|------|
| **来源层**（伤从哪来） | 来自他人——被抛弃、被背叛、被利用 / 来自自己——做错的选择、没做的事、说出口的话 / 来自世界——无法抵抗的力量、生来如此、运气 |
| **性质层**（伤是什么） | 具体的丧失——一个人、一件东西、一个地方 / 未解的谜团——不知道真相、不知道为什么、不知道是谁 / 被背叛的信任——信仰崩塌、誓言落空、规则失效 |
| **表现层**（伤怎么显现） | 身体上的痕迹——伤疤、疾病、衰老 / 反复浮现的记忆——噩梦里、独处时、某个声音让你想起 / 一个不能说出口的名字——秘密、耻辱、恐惧 |

**约束**：旧伤必须与起源的"初始危机"有内在联系但不完全相同。两个原创旧伤不得使用相同的维度组合。呈现时以人物感受为首句，不直接说"你的旧伤是……"。

玩家选定后：`--set scar "旧伤描述"`。

---

### 步骤 3：执念 (The Drive)

DM 读取所选起源的 `drive_options`，从中随机抽 1 个，再即兴原创 2 个。三个一起用 AskUserQuestion 呈现。

**即兴创作维度矩阵：**

| 维度 | 选项 |
|------|------|
| **方向层**（执念指向谁/什么） | 朝向某个人——找到、保护、复仇 / 朝向某个答案——理解、揭示、确证 / 朝向某个地方——到达、离开、回到 |
| **紧迫层**（为什么是现在） | 时间在流逝——某个东西在恶化、某个窗口在关闭 / 有人在等——一个人、一群人的处境取决于你 / 自己撑不了多久——身体、精神、环境的倒计时 |
| **代价层**（完成执念需要付出什么） | 需要放弃安稳——离开安全区、放弃伪装 / 需要背叛他人——选择伤害一个人来成全另一个人 / 需要面对自己——承认错误、放下骄傲、接受真相 |

**约束**：执念是誓言之前的原始驱动力——不是目标，是"为什么还没放弃"。应该与步骤 2 选择的旧伤形成呼应（旧伤是过去的，执念是指向未来的）。为 Act 2 的誓言选择埋下伏笔但不要预演。

玩家选定后：`--set drive "执念描述"`。

---

### 步骤 4：形貌 (Face & Form)

DM 读取所选起源的 `appearance_options`，从中随机抽 1 个，再即兴原创 2 个。三个一起用 AskUserQuestion 呈现。

**即兴创作维度矩阵：**

| 维度 | 选项 |
|------|------|
| **身体层**（被什么塑造） | 被环境塑造——白息、日晒、缺氧、化学品 / 被劳动留下——重复动作导致的身体变形、职业病 / 被过往刻下——伤疤、印记、磨损 |
| **姿态层**（怎么站、怎么动） | 戒备的——随时准备逃跑或战斗、习惯性观察 / 疲惫但撑着的——身体在发出信号但意志还在 / 安静到容易被忽略——学会了不被注意 |
| **反差层**（什么不符合第一印象） | 手与年龄不符——太老或太年轻 / 眼神与身份不符——太锐利、太茫然、太温柔 / 动作与处境不符——太从容、太警觉、太缓慢 |

**约束**：必须是感官描写——能看到、听到、闻到的具体细节。禁止泛化描述（"高大强壮"），禁止数字（"大约一米八"），禁止游戏术语。

玩家选定后：`--set appearance "形貌描述"`。

---

### 步骤 5：取舍 (The Weight)

荒原磨利了什么，又磨掉了什么？DM 提供 3-4 个纯叙事的调整选项。每个选项对应：一项属性 +1，另一项 -1。也提供"保持不变"选项。

**约束**：
- 两项属性变完后都必须在 1-4 范围内。若起源的某属性已是 1，排除该属性 -1 的选项；某属性已是 4，排除该属性 +1 的选项
- AskUserQuestion 选项描述中**绝对不能出现属性名和数值**——只写叙事后果（"你学会用身体说话，代价是越来越难信人"而非"躯壳 +1, 清明 -1"）
- 玩家选定后，DM 默默执行 `--update attr1 +1` 和 `--update attr2 -1`

---

### 步骤 6：命名

`--set player_name "名字"`。

### 原创起源规范

DM 在步骤 1 中即兴创建 2 个原创角色。每次从以下三个维度各取一项，组合成角色。两个角色不得使用相同的维度组合。

| 维度 | 选项 |
|------|------|
| **身份层** | 祭司助手 / 圣水走私者 / 守卫逃兵 / 禁地附近的拾荒者 / 灰质者接触者 / 基座信号监听者 |
| **危机层** | 知道某个人的秘密，但没法说出口 / 身上有一样东西，你不知道该还给谁 / 欠某个人的债——不是圣水，是人情 / 发现自己开始信不过自己的记忆 / 有一个约定，你一直没去兑现 / 有人在等你做一个决定，你拖得太久了 |
| **认知层** | 完全的信徒 / 半知情的怀疑者 / 知道一件真相但不知道其含义 / 曾见过不该存在的东西于是选择不信 / 相信自己的命运不在云室里 |

**约束**：
- 危机层是 DM 的内部设计锚点——起源描述中必须隐含危机的可能性，但 AskUserQuestion 呈现时不直接以危机为首句
- 大地点由身份层决定（见下方"起点位置"映射表），写入起源时注明
- 社会地位不得与抽到的固定起源重合
- 属性倾向：四项总和 = 8，单项 1-3
- 原创起源的 key 使用英文下划线格式
- 玩家选定原创起源后，DM 当场将起源内容追加到 `origins.md`，标注 `[来源：session_{日期}]`
- 属性钟在玩家选定后用 `--set_clock` 执行
- 原创起源需要 DM 当场为步骤 2-4 即兴创作选项（维度矩阵见上方各步骤），**不写回 origins.md**（旧伤/执念/形貌是个人叙事，不是共享世界数据）

### 起点位置

每个起源绑定一个大地点。DM 在大地点内随机选一个具体场景作为开场位置。命名完成后，以该场景为物理起点写开场叙事。

| 大地点 | location_id | 可选开场场景 |
|--------|-------------|-------------|
| **祭坛区** | `altar_district` | ① 圣樽台阶下——石缝渗着圣水残渍 ② 圣水配给队列旁——清晨的队还没排起来 ③ 祭坛后殿——祭司们低声争论着什么 ④ 香炉室——没人注意到炉火快灭了 |
| **低地边界** | `lowland_boundary` | ① 废弃营地——远征队的篝火余烬还温着 ② 白息最淡的岩缝——唯一能看到星空的位置 ③ 弃子被丢下的路口——火把光最后消失的方向 ④ 枯萎者标记石——被划掉的远征队编号 |
| **禁地附近** | `forbidden_zone` | ① 锈蚀金属门——升降梯出口，旧世界文字被炭灰涂抹过 ② 旧世界标识牌——上面的字你只能读懂一半 ③ 基座信号接收范围内——冷白荧光在远处规律闪烁 ④ 禁地边缘——地面从盐壳突然变成了平整的旧世界铺装 |

DM 原创起源的大地点根据身份层确定：

| 身份层 | 大地点 |
|--------|--------|
| 祭司助手 / 守卫逃兵 | 祭坛区 |
| 圣水走私者 / 灰质者接触者 | 低地边界 |
| 禁地附近的拾荒者 / 基座信号监听者 | 禁地附近 |

### 开场白原则（硬约束）

- 第一句是处境，不是背景——禁止以"云室是一个……"开头
- 没有世界观介绍——不解释白息、圣水、酿主是什么
- 玩家读完只知道一件事：现在很糟糕
- 玩家不是旁观者——开场白发生在玩家身上，不是玩家面前
- 第一个选择在开场白结束时自然出现
- 必须优先写身体与感官压迫，不得先写抽象判断与主题概括
- 开场叙事中应自然地融入角色的旧伤、执念和形貌——不是逐条罗列，而是在处境中让这些线索自己浮现

```

然后你听到了破碎的声音。

一只圣樽从供台上滚落，在台阶上磕出三个缺口，
液体洒在你手背上——透明的，有点呛，
和你想象中神明的血液完全不一样。

没有人看见。只有你。
```

```
他们没有回头。

你看着火把的光在白息里越来越小，最后消失。
你的腿还能动，但队长说你的眼睛开始发黄了——
那是枯萎症的第一个迹象，他说，
带你回去只会害了所有人。

低地的白息比干岸浓得多。

```

#### 基座流放者

```
升降梯关上的声音很轻。

你甚至没有时间说什么——两个技术员架着你的胳膊，
第三个按下了按钮，然后地板开始上升。
你最后看到的是走廊尽头那台服务器的绿色指示灯，
还在闪，和过去二十年一样规律。

然后是光。

不是基座的冷白荧光，是另一种光——
散漫的，带着某种说不清楚的颜色。
空气里有什么东西，呛，但不像毒。
你的肺不知道该怎么处理这种空气。

```

开场白结束后，查 `world_constants.json` 获取玩家所在位置的感官细节，用于叙事衔接。

> **世界认知不在创建时选择**。酿主、圣水、基座、灰质者——这些概念玩家在开局时一无所知。DM 在叙事中埋线索，当玩家通过行动或判断接触到真相时，执行 `--set_truth <维度> <值>` 锁定。各维度的可能走向和发现条件见 `truths.md`。

## 三、世界专属机制

### 白息侵蚀

每进入新地点，DM 查 `world_constants.json` 中该地点的 `white_breath_level`：

| 等级 | spirit 推进 | 叙事表现 |
|------|-----------|---------|
| `low` | 每 3 轮 +1 | 几乎感觉不到 |
| `medium` | 每 2 轮 +1 | 头重、视野边缘模糊 |
| `high` | 每轮 +1 | 声音失真、分不清方向 |
| `extreme` | 每轮 +1 + 枯萎症判定 | 幻觉与现实不分 |

DM 静默执行 `--update spirit +N`，只在叙事中通过感官描写体现——不直接报告数字变化。

### 枯萎症叙事规范

```
spirit 0     正常，无症状
spirit 1-2   早期：偶尔看到不存在的影子，声音有轻微回响
spirit 3     中期：分不清某些记忆是真实还是幻觉，NPC对话有时"变形"
spirit 4     晚期：DM 可在叙事中插入玩家不确定真假的内容
spirit 5     触发 Face Desolation
```

- 必须将“对话变形”写成措辞偏移与语义错位，不得直接解释为系统效果或数值阶段

### Face Desolation

spirit 满格（≥5）时执行。掷 1d6：

```
python .claude/skills/rpg-dm/scripts/tools/state_mgr.py --face_desolation
```

| 掷骰 | 结果 | 效果 |
|------|------|------|
| ≥6 | 强成功 | spirit-2，继续 |
| 3-5 | 弱成功 | 留下永久标签【desolation_scarred】，spirit-1，继续 |
| ≤2 | 失败 | 精神永久崩解，游戏结束 |

### 圣水使用

若 `world_truths.holy_draught_effect` 未锁定，DM 根据叙事判断本次效果——圣水可能恢复 spirit，也可能只是暂时缓解。效果不必每次一致，直到玩家形成明确判断后执行 `--set_truth` 锁定。

- 必须允许短期叙述矛盾并保持留白，不得在锁定前给出唯一解释

锁定后的效果：
- **spirit_anchor**：恢复 spirit
- **physical_antibody**：恢复 health
- **cursed_source**：恢复选择轨道，但触发【依赖】标签检定

### 战斗伤害轨道

云室的伤害轨道为 `health`（由 `default_state.json` 的 `combat_damage_attr` 指定）。`combat.py --tick_constitution <N>` 实际更新的是 health 轨道的 filled 值。

## 四、主线四幕协议

云室会话必须遵循四幕主线推进：

1. 窒息开场（生存压迫 + 线索播种）
2. 真相锁定（2-3 次 truths 锁定）
3. 血酒立誓（三誓言选择 + 目标时钟启动）
4. 终结回写（finale 判定 + world mutation + 结尾分叉）

完整执行细则见 `mainline_arc.md`。DM 必须按该协议推进，不得长期停留在无目标游走状态。协议是叙事流程约束，不改变属性、轨道、誓言、结局系统既有机制。

## 五、誓言选择

在前 2-3 次真相锁定后，DM 在叙事中提供誓言契机——一个让玩家必须做出选择的情境。

### 选择流程

1. DM 从 `oaths.md` 固定池随机抽 1 个
2. DM 按 `oaths.md` §原创誓言规范即兴创作 2 个
3. 三个一起用 AskUserQuestion 呈现（不标明哪个来自固定池）
4. 玩家选定后：`--set_goal "誓言名"` → 玩家用自己的话宣告 → `--set_oath "玩家原话"`
5. 若玩家选的是原创誓言，DM 当场将其追加到 `oaths.md`，标注 `[来源：session_{日期}]`

### 原创誓言规范

见 `oaths.md` §原创誓言规范。三维度框架：

| 维度 | 选项 |
|------|------|
| **对象层**（誓言指向谁/什么） | 一个具体的人 / 一个地点 / 一个被隐藏的真相 / 一个正在发生的过程 |
| **规模层**（决定 DC） | 个人誓言 DC 10 / 地区誓言 DC 14 / 史诗誓言 DC 18 |
| **张力层**（誓言内部的矛盾） | 想要的与必须付出的冲突 / 完成誓言会伤害在乎的人 / 誓言可能基于错误前提 |

### 约束

- 两个原创誓言不得使用相同的维度组合
- 对象必须扎根于云室世界观——引用已有地点、NPC、或玩家已接触的真相
- 规模层至少有一个为个人或地区（避免两个都是史诗）
- `--set_goal` 自动从 `goal_definitions.json` 读取固定誓言的参数（DC、clock_max 等）；原创誓言需手动传入 JSON 属性

## 六、关键 NPC 对话回合协议（不新增机制）

每次与核心 NPC（`high_priest / old_scholar / plinth_scout / gray_elder / water_seeker`）发生关键对话时，DM 必须按以下顺序处理：

1. 读取当前关系档位（`--affinity "NPC名"`，默认 `stranger`）
2. 读取当前 `flags_active`（来自 `--view` / `--action`）
3. 读取已锁定 truth 与当前 oath/goal 状态
4. 判断当前话题属于该 NPC cognition 的哪一层（`knows / believes_wrongly / conceals / unaware_of`）
5. 按该 NPC 的 `dynamic_personality`（`affinity_expression` + `status_reflex` + `reveal_policy`）生成回应

输出必须包含三层：
- 表层台词（NPC 说出口的话）
- 潜台词（NPC 真实在保护或争取什么）
- 行为动作（停顿、回避、逼近、离场等）

硬约束：
- truth 未锁定前允许矛盾与留白，不得提前给唯一解释
- truth 锁定后允许立场冲突，但不得反向篡改已锁定事实
- `unaware_of` 内容禁止泄露
- 核心 NPC 禁止作为纯任务发放器；每次关键对话必须体现立场与代价
