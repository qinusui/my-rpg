# 云室主线四幕协议

> 本协议用于保证云室每局都能形成完整弧线：开场压力 → 真相锁定 → 血酒立誓 → 终结回写。
> 这是叙事流程约束，不改变属性、轨道、誓言、结局系统的既有机制。

---

## 幕一：呼吸之前

**设计意图**：玩家先成为一个人，再成为这个世界里的人。世界观通过行动的阻力自然渗透，不在开场解释。

**触发条件**：角色创建完成并进入第一个场景后立即生效。

**必须产物**：
- 1 个个人誓言场景（寻人 / 取回某物 / 赴约 / 完成承诺）
- 世界的异常作为**阻力**出现，而非主角

**执行要点**：
- 开场场景必须是日常尺度的：一个具体的人、一件具体的事、一个具体的地点
- 白息、枯萎、圣水等世界观术语**禁止在幕一主动解释**——只能通过 NPC 反应或环境细节暗示
- NPC 对世界异常的反应必须像呼吸一样自然——不讨论、不解释、不命名
- 世界的奇异感通过”事情没有按常理发展”来呈现，不通过旁白说明
- 个人誓言对象必须是情感驱动的、日常生活中可以理解的东西，禁止是对世界真相的探究
- 角色进入首场景前，DM 必须先完成一次”回声筛选”：从 chronicle 选择 3-4 条历史回声投放到前 2-3 场，禁止全量倾倒

**失败兜底**：
- 若 2 回合后个人誓言仍未推进，触发一个阻碍（NPC 失约 / 道路封锁 / 目标失踪），把压力加在誓言上而不是世界危机上

---

## 幕二：真相锁定

**触发条件**：幕一产物达成后进入。

**必须产物**：
- 锁定 2-3 个世界真相维度（`--set_truth`）
- 形成至少一个玩家立场冲突（相信版本A或B）

**执行要点**：
- 未锁定前允许叙事矛盾，禁止提前给唯一解释。
- 真相来源必须来自玩家行动接触，不得凭空揭示。
- 在每个待锁定 truth 维度上，锁定前至少出现一次来自核心 NPC 的偏见或遮蔽视角（`believes_wrongly` 或 `conceals`）。
- 历史回声在本幕只能用于”加压与扰动”（谣言冲突、关系摩擦、资源摩擦），不得直接替代 truth 锁定步骤。
- **硬约束**：叙事中揭示的真相必须在同回合内通过 `--set_truth <维度> <值>` 机械锁定。禁止将真相锁定推迟到会话结束——推迟意味着该真相不被系统计入，章节转场判据永久不满足。<!-- 修正：两次会话中 DM 在叙事里揭示了全部真相但从未调用 --set_truth，导致章节永远卡在 0 -->

**失败兜底**：
- 若 4 回合后仍未锁定第 2 个真相，必须给“证据型场景”（旧记录 / 设备读数 / 目击者证词）保障推进。

---

## 幕三：血酒立誓

**触发条件**：完成 2-3 次真相锁定后必须触发。

**必须产物**：
- 三个誓言选项（固定池 1 + 原创 2）
- `--set_goal` 成功写入当前目标
- `--set_oath` 写入玩家原话誓言

**执行要点**：
- 誓言对象必须锚定已出现的人/地/真相，不得脱离现有叙事。
- 立誓后进入目标生命周期，禁止长期无目标游走。
- 誓言场景必须出现至少一个核心 NPC 的立场反压（支持 / 阻挠 / 利用 / 退避其一），并受当前 affinity 与 flags 共同约束。
- 历史回声可以改变立誓代价与语气，但不得把誓言写成“上一局已经证明的唯一正确路径”。

**失败兜底**：
- 若玩家拒绝立誓，必须立刻给出延迟代价场景（资源断供 / 关系破裂 / 区域戒严），下一轮再次触发誓言选择。

---

## 幕四：终结回写

**触发条件**：目标时钟满格，或玩家主动宣告终结。

**必须产物**：
- 执行 `--finale_goal`
- 成功时执行 `--complete_goal` 并写入世界突变
- 结尾必须给分叉：就此封笔 / 继续前行

**执行要点**：
- 终结失败必须写灾难后果，目标可继续推进，不得软化为无事发生。
- 死亡/崩解分支按 endings 规则执行并写入 chronicle。
- 终结成功也必须回写至少一个“后续摩擦钩子”（势力反制、配给重分配、口径分裂、关系反噬其一），禁止写成世界问题被永久解决。

**失败兜底**：
- 终结失败后回到幕三中后段，继续围绕当前誓言推进；禁止重开誓言池。

---

## 幕间转场判据（DM 自检）

- 幕一 → 幕二：个人誓言遭遇第一次真正的阻力，且阻力来源指向更大的秘密
- 幕二 → 幕三：已锁定 2-3 个真相维度
- 幕三 → 幕四：active_goal 存在且 goal_clock 满格
- 幕四 → 结束/续行：finale 已结算并给出结尾分叉

## 命令对齐清单（不新增机制）

- 行动推进：`python .claude/skills/rpg-dm/scripts/tools/state_mgr.py --action --attr <属性> [--mod ±N]`
- 锁定真相：`python .claude/skills/rpg-dm/scripts/tools/state_mgr.py --set_truth <维度> <选择>`
- 立誓写入：`python .claude/skills/rpg-dm/scripts/tools/state_mgr.py --set_goal "誓言名"` + `--set_oath "誓言原话"`
- 推进目标：`python .claude/skills/rpg-dm/scripts/tools/state_mgr.py --tick_goal_clock`
- 终结判定：`python .claude/skills/rpg-dm/scripts/tools/state_mgr.py --finale_goal`
- 终结回写：`python .claude/skills/rpg-dm/scripts/tools/state_mgr.py --complete_goal ...`

## 会话结束自检（硬约束）

每次会话结束前（调用 `--end-session` 之前），DM 必须执行以下检视：

1. `--view` 查看 `章节` 字段——当前章节号是否与叙事进度匹配？
2. 若叙事已进入幕二但 `世界知识 (线索)` 仍为 0 → 补 `--add_clue`
3. 若叙事已揭示真相但 `world_truths` 缺失对应维度 → 补 `--set_truth`
4. 若已完成 2-3 次真相锁定但章节仍为 0 → 手动推进章节号
5. 禁止在章节号与叙事进度不匹配的状态下结束会话

**章节号与幕的对应关系**：
- 章节 0 = 幕一（窒息开场）
- 章节 1 = 幕二（真相锁定中 / 已完成）
- 章节 2 = 幕三（血酒立誓）
- 章节 3+ = 幕四（终结回写）

禁止 DM 在叙事中宣称"第X章完"而机械章节号仍为旧值。两者必须同步。<!-- 修正：两次会话 DM 在叙事中写"第一章完"但 state.json 章节始终为 0 -->

## 回归要求

- 本协议只约束叙事流程，不改 tools 行为。
- 任一失败都必须产生后果并继续可玩，不得“失败无成本”。
- 玩家始终保有选择权，DM 只负责给出代价明确的分支。
