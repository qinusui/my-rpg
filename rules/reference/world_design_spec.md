# 世界观设计规范

> 这份文档回答一个问题：**什么样的世界，能在这个引擎里跑起来？**
>
> 它不是格式手册——Claude 会自己读现有文件推断格式。它是**设计约束手册**：告诉你一个合格的世界必须有什么、不能有什么、为什么。

---

## 一、铁律：三条不可妥协的底线

每个合格的世界观必须满足以下三条。缺一条就不是能跑的世界——是设定碎片。

### 1. 有核心冲突

**定义**：一个驱动整个世界的张力，在所有地区都能被感知。

核心冲突不是"主线剧情"——它是世界的底色。玩家可以选择参与或绕开，但它必须存在。

```
破碎之冠的核心冲突：龙神封印在崩解。两千年前的封印正在失效。
  → 自由港感受不到地震，但暗影议会在为此分裂
  → 霜语城的矿道越来越深，矮人说石墙后有人在敲
  → 翡翠林地的古树开始枯萎——地脉能量在异变
```

**坏例子**："这是一个中世纪奇幻世界，有精灵和矮人。"  
**好例子**："帝国覆灭后，三个继承者争夺王座——而王座下的地脉正在污染所有施法者。"

### 2. 至少有一个不可逆的失败条件

**定义**：如果玩家什么都不做、或做错了关键选择，世界会真的恶化。不是"任务失败请重试"——是世界状态永久改变。

```
破碎之冠的失败条件：
  - 封印彻底崩解 → 龙神苏醒 → 坏结局
  - 关键 NPC 被暗影议会控制 → 信息源永久丢失
  - 碎片被敌对势力获取 → 结局路线被锁定
```

失败不等于游戏结束（见引擎规范 §8）。但失败必须留下痕迹——进度钟满格不是"下次注意"，是"事情已经发生了"。

### 3. 有认知缺陷的 NPC（至少 3-5 个）

**定义**：每个重要 NPC 都有四个认知维度中的至少两个：

| 维度 | 含义 | NPC 表现 |
|------|------|---------|
| `knows` | 正确知道的事 | 正常陈述 |
| `believes_wrongly` | 错误相信的事 | 自信地说出错误内容 |
| `conceals` | 有意隐瞒的事 | 回避、转移话题、半真半假 |
| `unaware_of` | 不知道的事 | 真实的茫然、猜测、沉默 |

**为什么这很重要**：全知 NPC 是平坦的信息终端。玩家问什么 NPC 答什么 = 没有探索，没有误解，没有惊喜。

**坏例子**：一个酒馆老板知道所有碎片的位置、所有势力的秘密、所有结局路线。  
**好例子**：马库斯知道第一片碎片的来历，但以为碎片只是值钱的古董——他不知道它跟龙神封印有关。他在这一点上是 genuinely 无知的。

认知缺陷不是 NPC 的"弱点"——是他们作为人的特征。每个 NPC 活在自己的信息茧房里。

## 二、结构性约束

### 地点设计

每个地点必须有三层信息：

```
sensory:   always (始终存在的感官) / sound (声音) / mood (氛围)
narrative: 谁在这里 / 他们在做什么 / 他们之间的矛盾是什么
mechanical: 遭遇表 danger_max, danger_tick, omens / 怪物池 / 环境事件关键词
```

**禁止**：只有名字的地点。`"frosthold": "北方矮人城"` 不是地点——是占位符。

### 怪物设计

每个怪物必须回答：
- 它在什么环境下出现？（决定遭遇表和背景图）
- 它的威胁来自什么？（数量？单个强度？环境配合？）
- 玩家可以用什么非战斗方式应对？（决定了代价库中"和平解决"是否可用）
- 它的掉落/生态位是什么？（不只是"掉金币"——它在世界中的位置）

### 物品设计

物品分四层，不是所有物品都需要战斗数据：

```
武器/防具 → items.json 中记录名称和叙事属性（材质、外观、来历）。战斗数值由 DM 根据叙事现编，无需 dice/bonus/ac
消耗品   → 效果在 items.md 中描述，DM 执行对应的 --update
任务物品 → 必须有 effect 描述（它为什么重要）
传说物品 → 必须有 property 字段（它为什么特殊）+ 叙事代价
```

### 遭遇表设计

原则：**每个地点通过危机钟（danger_max + danger_tick）控制遭遇频率。danger_max 越低、danger_tick 越高 = 越危险。**

```
danger_max 5-6, danger_tick 1d4  = 极危险区域（裂口、废墟深处）——约 2 tick 触发遭遇
danger_max 6-8, danger_tick 1d3  = 中等危险（荒野、矿道）——约 3-4 tick
danger_max 10-12, danger_tick 1d3 = 相对安全（城市、港口）——约 5-6 tick
danger_max 14+, danger_tick 1d2   = 极安全（圣地、已解放区域）——约 9+ tick
danger_max 20, danger_tick 1d2    = 特殊（最终 Boss 区域）——遭遇=剧情事件
```

每个地点必须定义 omens（感官线索），在危机钟越过阈值时返回，供 DM 在叙事中埋 foreshadowing。

遭遇池中的怪物必须与该地点的叙事一致。荒野不会出现城市守卫，矿道不会出现海盗。

**复合实体**：如果一个概念同时是地点和遭遇类型（如"嗜醇林"——既是可到达区域，也是其他地区可能遭遇的环境危害），必须同时满足两边的格式要求：
- 作为地点：在 `world_constants.json` 中有 sensory/mood/white_breath_level，在 `encounter_tables.json` 中有独立条目
- 作为遭遇：在 `bestiary.md` 中有生态描述，在 encounter pool 中仅出现在生态合理的地区

### 进度钟设计

每个世界观至少需要 2-3 个世界级进度钟。它们不是"任务倒计时"——它们是**世界在玩家不在场时自己运转的证据**。

```
破碎之冠的进度钟：
  - 封印崩解 (8格)：整个世界的压力源
  - 暗影议会分裂 (6格)：在玩家介入前就开始了
  - 月圆之夜 (8格)：每 5 tick 推进——世界有自己的节奏
```

## 三、禁止清单

以下内容不出现在任何合格的世界观中。如果 Claude 在生成时违反了这些，直接打回。

### 角色设计禁区

- **全知 NPC**：知道所有答案、能解释所有谜团的角色
- **没有任何认知缺陷的 NPC**：只说实话、完全透明的人不存在——NPC 也是
- **纯粹的"任务给予者"**：只为发任务而存在的 NPC。每个 NPC 必须有自己的生活、矛盾、目标
- **无敌意的势力**：所有势力都友好 = 没有真正需要选择的事情

### 剧情设计禁区

- **线性到没有分支的主线**：只有一个方向、玩家走岔就被拽回来
- **没有代价的选择**：所有选项都是好的、失败没有后果
- **"意外地"成功**：大失败被 DM 转化成"虽然失败了但是发现了别的东西"
- **预设的"正确"路线**：DM 知道哪条路最好。玩家应该面对真实的选择困境——不是"猜 DM 的心思"

### 世界设计禁区

- **只有名字没有感官的地点**：玩家无法"看到"或"听到"的地方 = 不存在
- **独立于世界的怪物**：怪物不和任何地点、势力、生态绑定 = 只是数据
- **没有叙事代价的传说物品**：强大的物品必须有不方便的地方
- **没有内在矛盾的和平世界**：一个所有势力都和平共处的世界没有故事可讲

## 四、世界观规模指南

不是越大越好。一个可玩的世界观有这些就够了：

### 最小可行世界观

```
核心冲突：1 个
主要地区：3-5 个（每个有感官描述 + 遭遇表 + 1 个地区性冲突）
NPC：8-15 个（每个有认知缺陷）
怪物：5-8 种（与地区绑定）
物品：8-12 种（武器/防具/消耗品/任务物品各几个）
进度钟：2-3 个（世界级）
结局路线：2-3 条（不是"好/坏"——是不同方向的选择）
```

破碎之冠超过这个规模——它是旗舰世界观。但最小可行版本足够跑出有深度的 3-4 小时游戏。

### 什么时候一个世界观"太大了"

- 玩家不可能在一次游玩中访问所有地区 → 地区间需要"选择去哪"的张力
- NPC 数量超过 20 → 玩家记不住，不如减少 NPC 但加深每个人的认知缺陷
- 结局超过 3 条 → 玩家做选择时不是在选方向，是在瞎猜

## 五、生成协议：把一句话变成世界

当用户给 Claude 一句话描述时，Claude 按以下顺序生成：

### Phase 1：核心定义（先问 3 个问题）

```
1. 核心冲突是什么？（用一句话定义世界的驱动力）
2. 失败的底线在哪里？（世界最坏能坏到什么程度）
3. 这个世界里"英雄"的定义是什么？（决定了角色创建选项的风格）
```

### Phase 2：骨架搭建

```
1. 3-5 个主要地区（每个有 三层信息：感官/叙事/机械）
2. 2-3 个势力（有矛盾，有认知盲区）
3. 5-8 种怪物（与地区绑定）
4. 6 个角色创建选项（种族 2-3 个、职业 3-4 个、过往 4-6 个、目标 3-5 个）
```

### Phase 3：血肉填充

```
1. 8-15 个 NPC（每个有 traits/quirk/voice/cognition）
2. 8-12 种物品
3. 2-3 个世界级进度钟
4. 后果库（轻微/实质/致命的失败代价）
5. 遭遇表和环境事件
```

### Phase 4：验证

生成完成后，Claude 自检：

**单文件完整性**：
- □ 每个地点有三层信息（sensory/narrative/mechanical）？
- □ 每个 NPC 有至少两个认知缺陷维度？
- □ 有至少一个不可逆的失败条件？
- □ 没有全知 NPC？
- □ 所有怪物都绑定了地点？
- □ 结局是真实的选择分歧而非"好/坏/真结局"？

**跨文件一致性**（必须通过，不可跳过）：
- □ `world_constants.json` 中的每个地点，在 `encounter_tables.json` 中都有对应的条目？
- □ `encounter_tables.json` 所有 pool 中的怪物 key，都在 `bestiary.md` 中有定义？
- □ 每个 encounter pool 中的怪物，与该地点的生态环境一致？（盐碱地不出嗜醇林、祭坛区不出野生龙眷）
- □ `world_constants.json` 中 NPC 引用或持有的物品，都在 `items.json` 中有条目？
- □ `origins.md` 中每个起源都有 `key` 字段（英文下划线格式）？
- □ `default_state.json` 的四项属性 filled 之和 = 8？
- □ `oracle.json` 中每个条目都有至少 3 个 `variations` 子项？

## 六、与引擎的契约

世界观文件一旦生成，引擎不修改其结构。以下文件由引擎消费——世界观设计者只需确保它们存在且格式正确：

| 文件 | 引擎消费方式 | 设计者责任 |
|------|------------|-----------|
| `character_options.json` | 角色创建时读取 | 种族/职业/过往/目标必须各有 meaningful 的区别 |
| `bestiary.json` | 战斗初始化时读取名称映射 | 怪物必须绑定地区，出没环境和叙事钩子写在 bestiary.md 中 |
| `items.json` | 装备管理时读取物品清单 | 传说物品须有 property，武器/防具记录名称和叙事属性即可 |
| `world_constants.json` | DM 叙事时查表 | NPC 必须有 cognition 块，地点必须有 always/sound/mood |
| `encounter_tables.json` | `--tick` 时危机钟推进 | danger_max/danger_tick 控制频率，omens 提供 foreshadowing，怪物池与地点叙事一致 |
| `environment_events.json` | 战斗间隙 DM 可选触发 | 事件类型与地点环境匹配 |
| `consequences.md` | D20 失败时 DM 查表 | 每级代价必须多样化——不只是"掉血" |
| `threshold_rules.json` | `--view` 自动计算 | 标志必须有叙事意义——不是"力量大于 10" |
| `default_state.json` | `--init` 时使用 | 属性钟默认值反映"普通人"水平 |

引擎不读取 `world.md`（仅供 DM 参考）——但它是 DM 理解世界的入口，必须写清楚。
